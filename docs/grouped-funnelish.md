# Faithful grouped Funnelish checkout

The importer recognizes explicit `product-id_main_product` radio controls, `product-id_shipping_product` radio controls, and `product-id` add-on checkboxes. It reads `FUNNEL`, `STEP` and `PRODUCTS` configuration without executing source scripts. The source currency, exact configured prices, availability flags and checked defaults are authoritative. Source promotional package labels remain labels; no item counts, discounts or gifts are inferred from them.

Main packages become variants of the named source product. An explicit hidden `data-source="currentProduct"` reference can supply the family name; its price is never substituted for package prices. Delivery controls become independent owned shipping rates, with no invented free threshold. Visible add-on controls become separate hidden-from-browsing catalog products that are selectable only within their matching checkout group. They are not alternative main packages. Unknown stock quantity remains untracked (zero inventory with backorders allowed when the source explicitly says available), rather than manufacturing a stock count.

Package quantity multiplies package price only. Add-ons remain one independent line each; delivery is one selected rate. Changing the main package preserves add-ons, shipping, contact details and discount code. Replacing the selected add-ons is explicit and validated against the current group. A duplicate receives new catalog, page, media and shipping IDs; source identifiers remain provenance. Merchant page edits and revision restoration preserve the underlying mappings.

Source and native controls share the owned checkout endpoints and server totals. A database failure rolls back the cart transaction and restores the previous UI selection. Shipping failures also restore source and owned radios. Checkout updates are serialized in the browser, and later server cart changes invalidate a pending package update. Preview payments remain disabled.

Unsupported selectors, ambiguous shipping defaults, hidden selected defaults, missing availability, incompatible currency or price precision, recurring products, variant matrices, multiple shipping scopes and unmapped catalog records remain visibly blocked. Hidden unchecked controls are retained in the catalog and copy report without creating a new purchase option. Their custom behavior needs merchant interpretation before publishing. Source scripts, payment sessions and post-purchase provider integrations are not duplicated. A successful mapping does not imply pixel parity or complete asset capture.

Validation: `npm test`, `npm run typecheck`, `npm run test:grouped`, and the existing imported-commerce, imported-media, imported-bundles, funnel-checkout and course-review browser tests. The private public-template evaluation captures Froozly's landing and checkout pages, exercises exact USD totals and its duplicate, and blocks external traffic and preview payments. No copied assets or private provider prompts are checked into this repository.
