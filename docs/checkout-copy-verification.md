# Imported checkout verification

The public Froozly Funnelish template uses `.payment-form` inside `.section_row`, rather than the older `.fk-card-payment-container` / `.basic-information-section` shell. Falling back to prepending the entire native form left both checkouts visible. Modern grouped templates now mount the owned payment form in the source payment slot; retain source package, shipping and add-on controls; and replace the source submit anchor with the single owned submit button bound to that form.

Named source contact/address fields bind to the owned form. The source's `shipping_state` input is only treated as the street address when its explicit visible field label is exactly “Street Address”; other state fields keep their state meaning. Missing optional address fields use readable labels and the source border/background treatment. The removed-script phone-prefix widget becomes one native phone input. Inline validation supports both native `.field` and imported `.form-element` wrappers. Shipping recaps match exact source-card content, excluding embedded CSS/scripts, and follow confirmed shipping selection. Native fallback shipping controls remain mounted for quotes and rollback but are hidden when source controls are bound.

Imported `.faq` headers receive click/keyboard behavior and accessible expanded state. Source videos use native controls; a media error is reported explicitly. Signed remote source videos are not guaranteed to remain playable or to become owned media. Unknown source interactions still need merchant review. Source payment sessions, wallet credentials and executable source scripts are never copied.

`test/modern-funnelish.browser.mjs` reproduces this structural failure using fictional merchandise and no copied source artwork. At 1440/390/320 pixels it checks that only one checkout exists, no duplicate visible selectors remain, payment fills its source slot, optional labels stay readable, source fields participate in FormData/inline validation, each package/rate/add-on is operable without forced clicks, billing and FAQ toggles work, shipping recaps update, video failures are explicit, preview payment is disabled, and a duplicate binds to its own catalog. These tests fail against the preceding release. Actual private Froozly captures and interactions are reviewed separately; fixture assertions alone do not establish source visual fidelity.

## Shopify distinction

A copied Shopify storefront and Shopify's hosted checkout are different surfaces. `ensureCopiedCheckout` builds an owned editable checkout when no public checkout page exists. It follows the one-page hierarchy and responsive form/summary design, with merchant branding and supported Stripe methods. It does not duplicate Shopify-hosted payment sessions, Shop Pay, Shopify sign-in, customer account rewards, tax services or merchant-specific checkout extensions. Show only features the owned backend actually supports. Empty product-image URLs render a neutral accessible placeholder rather than a broken image.

Shopify source comparison uses its official [one-page checkout examples](https://www.shopify.com/enterprise/blog/one-page-checkout). This desktop reference supports the general form/summary hierarchy, not a pixel-parity or mobile fidelity claim. A GET-only visit to the public Dawn demo `/checkout` without a cart redirected to its home page; no source cart mutation or live checkout submission was performed. Native fixture coverage at 320/390/820/1440 pixels includes colors, labels, mobile summary, discount errors/removal, shipping, separate billing, country changes, provider address failure/manual fallback, and mocked wallet confirmation. No real charge is exercised by these tests.
